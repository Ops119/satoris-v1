Private inference · Solana · x402

AI that can't read your prompts, paid per request.

Satoris seals each prompt to a GPU enclave the client has verified itself, charges for it in USDC over HTTP 402, and anchors a receipt on Solana. No accounts, no API keys, and no operator who can see the data.

The problem

Every AI API today runs on trust in the operator.

Prompts are readable

Hosted models see every prompt and completion. A privacy policy is the only guarantee, so health, legal, financial and source-code workloads stay off them.

Agents can't sign up

Accounts, API keys and monthly invoices are built for people. Autonomous agents need to pay per call with a budget, from a wallet, with no onboarding.

GPU networks can't prove anything

Decentralized GPU markets have cheap capacity, but a buyer can't tell what code ran or whether anyone looked at the data.

How it works

Four steps on every request.

Each step is already implemented in the repository and covered by tests.

1 · Verify

Check the enclave

The client sends its own nonce and checks the hardware quote: approved image, no debug mode, and the encryption key bound inside the quote.

2 · Seal

Encrypt to that key

The prompt is encrypted on the device (X25519 + AES-256-GCM). Only model and token cap stay readable for billing, and altering them breaks decryption.

3 · Pay

Settle in USDC

HTTP 402 quotes the maximum; with the upto scheme only the tokens actually used are settled. Failed requests are never charged.

4 · Prove

Anchor a receipt

Each job gets a receipt of hashes. Batches are rolled into a Merkle root stored by the Satoris program on Solana.

Why now

Three pieces became real at the same time.

Confidential GPUs

NVIDIA Hopper and Blackwell GPUs run in confidential-computing mode alongside Intel TDX and AMD SEV-SNP, with remote attestation from the vendor.

x402 payments

HTTP 402 became an open payment standard with official SDKs, hosted facilitators and Solana support, including usage-based settlement.

Agents that spend

Software agents now buy compute and data on their own. They need a wallet-native API with spend limits, not a signup form.

Roadmap

Lean phases, each with a test it must pass.

About 11 to 14 weeks of build with a small team, plus audit time, to a mainnet beta.

Phase 0 · Harden

~1 week

Request limits, persistent receipts, real devnet payments end to end, program tests in CI.

Phase 1 · Real attestation

~2–3 weeks · critical path

Intel TDX and NVIDIA H100 quotes verified in the gateway and in the browser, from a reproducible, measured node image.

Phase 2 · On-chain trust loop

~2 weeks

Approved images on-chain, nodes routed from the on-chain registry, receipt inclusion proofs any user can check.

Phase 3 · Payments polish

~1–2 weeks

Per-token settlement by default, sealed streaming, and an MCP tool so agents can call Satoris directly.

Phase 4 · Providers and app

~3–4 weeks

Self-serve GPU provider onboarding with USDC stake, weekly payouts, and a web app that verifies enclaves in the browser.

Phase 5 · Mainnet beta

~2 weeks plus audit

Program audit, launch caps, admin pause, multisig authorities, and AMD SEV-SNP support.

Business model

A take rate on private inference.

Usage fees

Every request settles in USDC. Satoris keeps the spread between the catalog price and the provider payout, visible in each receipt.

Provider stake

GPU operators stake USDC to receive traffic. Stake backs the network's guarantees without a speculative token.

Private deployments

Teams with regulated data can pin requests to their own attested nodes and keep verifiable receipts for audits.

For investors

Building the trust layer for AI that agents and regulated teams can use.

The code is open and runs today on devnet. Funding goes to the critical path: real hardware attestation, a first confidential-GPU provider, and an audited mainnet beta.
