Technology

Privacy you can check, not a policy you have to trust.

Every request is verified, sealed, paid for and recorded. The client does the checking itself, so the gateway in the middle never has to be trusted with data.

How it works

Four steps on every request.

Each step is already implemented in the repository and covered by tests.

1 · Verify

Check the enclave

The client sends its own nonce and checks the hardware quote: approved image, no debug mode, and the encryption key bound inside the quote.

2 · Seal

Encrypt to that key

The prompt is encrypted on the device (X25519 + AES-256-GCM). Only model and token cap stay readable for billing, and altering them breaks decryption.

3 · Pay

Settle in USDC

HTTP 402 quotes the maximum; with the upto scheme only the tokens actually used are settled. Failed requests are never charged.

4 · Prove

Anchor a receipt

Each job gets a receipt of hashes. Batches are rolled into a Merkle root stored by the Satoris program on Solana.

The gateway is a router, not a custodian.

Under the hood

The building blocks.

Standard, reviewable primitives. Nothing proprietary sits in the trust path.

Prompt encryption
X25519 key exchange, HKDF-SHA256 and AES-256-GCM through WebCrypto, so the same code runs in browsers and Node. Model and token cap are bound as authenticated data. X25519-HKDF-SHA256-A256GCM
Enclave checks
Client-chosen nonce, quote freshness, approved image measurement, TCB status, debug mode off, GPU evidence, and the encryption key bound into the quote's report data.
Hardware
Intel TDX and AMD SEV-SNP guests through the Linux configfs-tsm interface, with NVIDIA Hopper and Blackwell confidential computing for the GPU.
Payments
x402 v2 with the official SDK on Solana. exact charges the quoted maximum; upto settles only the tokens used. Requests that fail are never charged.
API
OpenAI-compatible /v1/chat/completions and /v1/models, a sealed endpoint, node attestation relay and receipt lookup.
On-chain program
Anchor program with nine instructions: node registry and USDC staking, attestation records, receipt Merkle roots, slashing and unbonding.
Logging
Method, path and status only. No bodies, headers, IP addresses or wallets.
